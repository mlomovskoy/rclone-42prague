# Excluded from sync. Lines starting with "- " are excludes.
# .git is deliberately NOT excluded — repos sync whole.
#
# A global carve-out for .git/info/exclude, ordered ahead of any future
# per-repo "- .../.git/**" rule a later change might generate at onboarding
# time (nothing generates that exclude yet, so this is currently a harmless
# no-op: with no ".git/**" rule anywhere yet, .git/info/exclude already
# syncs as part of the whole .git/ tree, same as before this line existed).
# Pre-positioned now so the ordering is already correct whenever that
# lands, rather than something to remember to insert above it later.
#
# The "**/" prefix here is deliberate and confirmed correct, not the bug the
# next paragraph warns about: unlike a single-segment pattern (*.o), this is
# a multi-segment path containing "/", which rclone anchors to the filter
# root UNLESS it starts with "**/" -- tested directly: a bare
# ".git/info/exclude" (no "**/") matched NOTHING in a real rclone run,
# against fixtures one and three directories deep, because no repo under
# this toolkit's $LOCAL_PATH ever sits AT the sync root itself (there's
# always at least the project-folder segment before ".git"), so the "**/
# needs one real directory component first" gap the next paragraph
# describes for single-segment globs never actually applies here.
+ **/.git/info/exclude
#
# IMPORTANT: never prefix a pattern here with "**/" to mean "at any depth
# including the root" -- in rclone's filter syntax, "**/" requires at least
# one real directory component before it, so "**/*.o" silently misses a .o
# file sitting at a project's own top level (only catches it nested under a
# subdirectory). A bare pattern like "*.o" already matches at every depth,
# root included -- that's what every rule below uses. Found the hard way:
# **/*.o and **/.cache/** had this exact gap since this filter file was
# first created, on every machine, the whole time -- confirmed with a
# scratch fixture that only the bare form catches a root-level match. Use
# /pattern (leading slash) only when you deliberately want root-ONLY, never
# root-plus-deeper.
- .DS_Store
- .Trash-*/**
- *.o
- *.out
- a.out
- .cache/**
# .claude/ itself is NOT excluded -- Claude Code's own runtime/session state
# lives entirely outside ~/Projects (in the user's home directory), not in
# a project-level folder, and no such top-level folder has ever actually
# existed in practice. An earlier version of this rule excluded
# ".claude/**" (later anchored to "/.claude/**") on that mistaken premise,
# and it silently blocked a project's own git-tracked, secret-free
# .claude/settings.json (e.g. a shared permission allowlist) from ever
# syncing -- on any machine that received the repo via bisync rather than a
# real git clone, that file would then look permanently "deleted" to git,
# since the working tree copy could never materialize. See TROUBLESHOOTING.md.
# settings.local.json is the one real exception: Claude Code's own
# per-machine-override convention (confirmed by its actual content to carry
# a hardcoded absolute path from a specific past session) -- excluded at
# every level (bare pattern, not anchored), whichever project it's in.
- .claude/settings.local.json
# workspace.json (and its mobile counterpart) hold pure per-device UI state
# for an Obsidian vault -- which panes are open, window layout, cursor
# position -- not vault content. Obsidian's own community convention is to
# exclude these from sync/version control for exactly the reason
# settings.local.json needed excluding above: noise that causes needless
# churn on another machine, never something worth inheriting. Every other
# file under .obsidian/ (plugins, appearance, daily-notes config, etc.) is
# genuinely shared vault configuration and keeps syncing.
- .obsidian/workspace.json
- .obsidian/workspace-mobile.json
#

# TEMPLATE REFERENCE -- dotfiles/dotfolders other tools may create inside
# a project, and how to handle each. This is a reference, not a live
# ruleset: every line below is commented out (harmless if left that way)
# except the .claude/ and .obsidian/ rules above, which are active because
# their content was actually inspected in a real project first.
#
# THE RULE FOR ADDING TO THIS LIST: don't blanket-exclude OR
# blanket-include on a guess. The .claude/** saga above is the cautionary
# tale in both directions -- an assumption about "runtime lock state" that
# was never actually true silently blocked a real, wanted file from ever
# syncing, for as long as this tool existed, before anyone looked inside
# the folder. The entries below are backed by actual research (each tool's
# own docs/repo, checked September 2026), not guesses -- but tool
# conventions change across versions, so before uncommenting anything for
# real:
#   1. Read what's actually inside the folder in a real project -- don't
#      trust this list blindly forever; re-check if it's been a while.
#   2. Decide file-by-file: curated, shareable, secret-free project policy
#      -> sync it (and it belongs git-tracked too, if it isn't already).
#      Per-machine/session-accumulated state -- a hardcoded absolute path,
#      an auth token, UI layout, anything the tool itself calls
#      "local"/"session"/"cache"/"history" -> exclude it here, AND make
#      sure the project's own .gitignore excludes it too if it's ever at
#      risk of being committed by accident (this tool and git should
#      agree, not leave one silently disagreeing with the other).
#   3. Uncomment (or add) a precise rule for exactly what was found, and
#      say what you checked in the comment -- not a guess for a whole
#      folder based on its name alone.
#

# .env files are the single most likely place for real secrets, and unlike
# the rules above this isn't about machine-locality -- it's about not

# exception: by convention it's a template meant to be shared, holding no
# real secrets -- the include must come before the excludes below, since
# rclone filters take the first matching rule.
